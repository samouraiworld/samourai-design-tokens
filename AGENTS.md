# Working in this repository

These rules apply to humans and to coding agents alike. They mirror the console's `AGENTS.md`; the last three sections are specific to a token package.

## Language and style
- English for code, comments, docs, commits, PRs, and chat. French only for user-facing product copy, which does not live here.
- Commit message: one line, on the *why*. No trailers, no co-authors, no generator tags.

## Git
- Never commit to `main`. Feature branch (`feat/`, `fix/`, `chore/`, `docs/`) + pull request. CI green before review.
- One PR per task. A PR that touches `.github/workflows/` or `AGENTS.md` needs a second human reviewer.

## The source of truth
- `tokens.json` holds the design workstream's values, carried verbatim. Changing a value is a **design decision**, and it arrives as a PR here with the contrast gate green or with an allowlist entry that says who decided and what they decided. It is never a way to make a check pass.
- Never edit `dist/` by hand. It is generated by `scripts/build.mjs`; a hand edit is undone by the next build and is caught by the drift gate. If `dist/` is wrong, the generator is wrong.
- The build must stay a pure function of `tokens.json`: same input, byte-identical output, no clock, no environment, no network. A build that is not reproducible cannot be diffed, and a `dist/` that cannot be diffed is a copy.

## The gates
- Four checks, all in `npm test`: **grammar**, **contrast**, **drift**, **units**. A PR merges with all four green.
- A failing contrast pair goes into `contrast-known-failures.json` **only** with a written reason and the decision it is waiting on. An entry whose pair starts passing fails the gate, so the file cannot rot into a blanket exemption.
- A naming deviation goes into `token-grammar-exceptions.json` on the same terms.
- Never widen a check to make it pass. Deleting a pair, loosening a minimum, or making an unresolvable row a SKIP are all ways of shipping the failure with the check still green — which is worse than no check.
- A new colour needs a row in `contrast-pairs.json` before it needs anything else.

## Agents specifically
- Agents build; humans specify and review. Every task has a written spec and an acceptance test before code.
- Do not modify `AGENTS.md`, `CODEOWNERS` or CI workflows without an explicit human instruction in the task.
- Do not add a dependency. This package builds and tests on plain Node with none, deliberately: consumers install it from a git tag, where no install step runs.

## Decisions
- Architecture decisions are recorded in `docs/adr/`. A change that contradicts an accepted ADR must first supersede it with a new ADR.
